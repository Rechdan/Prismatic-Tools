Collapse `Brush` accordingly (e.g. to a plain color option).
- [x] 1.4 Add a `LoadedWidget::id()` accessor (`pub fn id(&self) -> &str`, returning the existing `id` field / folder name). Confirm `name()` already exists and is unchanged.

## 2. Rebuild the shell nav on NavigationView

- [x] 2.1 In `src/shell.rs`, **preserve** the existing `use_effect` window plumbing (`window::capture_hwnd`/`install_close_to_tray`/`hide`) verbatim at the top of the rewritten `tool_surface`, and keep the `tick`/`set_tick` `use_state`, the `slot` `use_ref`, and the `w.render(&set_tick, tick)` / reload machinery. These are not part of the nav and must survive.
- [x] 2.2 Replace the `View { Home, Widget, Config }` `use_state` with a `use_state::<String>` holding the current tag (default `"home"`).
- [x] 2.3 Build `menu_items: Vec<NavViewItem>`: always `Home` (`NavViewItem::new("Home").tag("home").icon(Symbol::Home)`); then, based on the widget load result — on success the widget item (`NavViewItem::new(w.name()).tag(format!("widget:{}", w.id())).icon(Symbol::Document)`), on a real load error a selectable error item (`NavViewItem::new(<folder id>).tag(format!("widget:{}", <id>)).icon(Symbol::Important)`), and on the empty notice (`NoWidgets`) **no widget item**; finally, always a **Configs** item last (`NavViewItem::new("Configs").tag("config").icon(Symbol::Setting)`). Note: `WidgetError` has **no `id()` accessor** — its `Manifest`/`Entry`/`Lua` variants carry an `id` field while `NoWidgets` does not, so add a small `WidgetError::id() -> Option<&str>` helper (Some → error item, None → no item).
- [x] 2.4 Route the content by tag: `"home"` → `home::view()`; `"config"` (the Configs item) **or** `""` (a reload deselection artifact) → `config_view(...)`; a `"widget:*"` tag → the widget content (the successful render, or the load-error text for the broken case); any other → home fallback.
- [x] 2.5 Wrap the resolved `right_content` **once** in a ~16-DIP padded container (replacing the deleted body `.margin(16)`) before handing it to the NavigationView, so every view is inset from the content-area edges. The wrapper MUST **stretch to fill** the content area (`VerticalAlignment::Stretch`, `HorizontalAlignment::Stretch`) — otherwise a size-to-content wrapper hands `home::view()`'s `scroll_viewer` an unbounded height and the README stops scrolling (see `docs/reactor-notes.md`: a `scroll_viewer` needs a bounded cell). Also update the now-stale `src/home.rs` comment that says a "Grid star cell bounds its height" (no such cell exists after this change).
- [x] 2.6 Construct `NavigationView::new(menu_items, padded_content)` with `.selected_tag(tag.clone())`, `.on_selection_changed(set_tag)`, `.pane_display_mode(NavigationViewPaneDisplayMode::Left)`, `.pane_toggle_button_visible(true)`, `.settings_visible(false)` (the built-in gear is disabled — its selection does not route through reactor; Configs is a real menu item instead), `.pane_title("Prismatic Tools")` (no `.header(...)`); return it as the window body.
- [x] 2.7 Pass the `SetState<String>` setter **directly** to `.on_selection_changed(set_tag)` (a fresh closure each render would detach/reattach the WinUI handler every render — churn, not a correctness bug). The setter stores the received tag (empty string included — it routes to config). There is no GitHub handling and no browser-opening code. Add a code comment documenting (a) the tag namespaces (`"home"` / `"widget:*"` / `"config"`, all real menu items) and that the built-in gear is disabled because its selection does not route through reactor, and (b) the **menu-rebuild invariant**: reactor rebuilds a changed `menu_items` via `menu.Clear()` + re-append; clearing a currently-selected MenuItem makes WinUI fire `SelectionChanged` with a null item collapsing to `""`. Since reload (the only `menu_items` mutator) is reachable solely from the config view, the only item selected during a rebuild is Configs itself, so `""` is routed to config to keep content stable. Do not add any menu-mutating action reachable from the Home or widget view without addressing this.
- [x] 2.8 Delete the now-dead custom nav machinery: the `nav_button` helper, the selection/hover `ControlFill`/`SubtleFill` overlays, the tapped-`border` widget card with its `on_tapped`/`on_pointer_entered`/`on_pointer_exited`, the `hovered` `use_state`, the `Auto/Star/Auto` three-row nav grid, the two-pane body grid, the pinned title label, and the `HyperlinkButton` GitHub entry.
- [x] 2.9 Keep `config_view` and its reload action behavior unchanged; ensure it renders when the tag is `"config"` (or the `""` deselection artifact) and that reload still bumps the tick without changing the active tag (stays on config; the Configs item stays selected when the menu is unchanged, and content stays on config via the `""` route when a widget-changing reload rebuilds the menu).
